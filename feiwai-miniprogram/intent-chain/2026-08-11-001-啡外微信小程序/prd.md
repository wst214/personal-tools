## 问题陈述

啡外咖啡店需要一款可上架的微信小程序：顾客打开就能认出品牌，从首页进入点单、加购、支付，拿到取餐号或选择外卖送到家，并能查看我的积分；店侧不再只靠到店口头点单。

## 方案

做微信小程序「啡外」：首页用品牌大图与推荐饮品建立识别，提供点单与门店入口；支持完整点单（含杯型/温度/甜度等选项）、购物车、微信支付、订单进度与取餐号、外卖送到家，以及查看我的积分。无不可妥协项；以上保留能力均需落地。

## 用户故事

1. As a 顾客, I want 在首页看到啡外品牌大图, so that 我能立刻认出这是啡外 [C01]
2. As a 顾客, I want 在首页有明显的点单入口, so that 我能马上开始点餐 [C02]
3. As a 顾客, I want 在首页看到本期推荐饮品, so that 我知道现在主打什么 [C03]
4. As a 顾客, I want 从首页进入门店信息, so that 我能看到地址和营业时间 [C04]
5. As a 顾客, I want 浏览菜单并选择杯型温度甜度后下单, so that 我能点到想要的那杯 [C05]
6. As a 顾客, I want 使用购物车加购和改数量, so that 我能一次结算多杯 [C06]
7. As a 顾客, I want 支付后看到取餐号或制作进度, so that 我知道什么时候来取 [C07]
8. As a 顾客, I want 用微信支付完成付款, so that 我能在小程序里直接结账 [C08]
9. As a 顾客, I want 查看我的积分, so that 我知道消费攒了多少分 [C09]
10. As a 顾客, I want 选择外卖送到家, so that 我不用到店也能收到咖啡 [C10]

## 实现决策

- 客户端：微信小程序原生（WXML/WXSS/JS 或等价 TypeScript）；Tab/页面至少覆盖首页、点单、订单、我的。
- 服务端：独立后端（或微信云开发）承载菜单、购物车结算、订单、积分、门店信息；订单与积分需持久化。
- 支付：接入微信支付（小程序支付），支付成功后生成/更新订单并展示取餐号或制作进度。
- 履约方式：下单时可选到店自取或外卖；外卖需填写配送地址。
- 品牌：首页品牌大图与主题色对齐 `design/feiwai-logo.png`（橙/蓝）。
- 管理端：首版可用配置/后台简单维护菜单、推荐、门店信息；不做复杂运营中台。

## 验收标准

### P01: 打开认识啡外

对应 User Stories: 1, 2, 3, 4

- **Given** 顾客已打开啡外微信小程序且进入首页
- **When** 顾客浏览首页内容
- **Then** 能看到啡外品牌大图/Logo，可认出品牌
- **And** 能看到本期推荐饮品
- **And** 能找到点单主入口
- **And** 能找到门店入口并查看地址与营业时间

### P02: 到店点单支付取餐

对应 User Stories: 2, 5, 6, 7, 8

- **Given** 顾客在首页，菜单与支付可用，选择到店自取
- **When** 顾客点「点单」→ 选饮品与杯型温度甜度 → 加入购物车 → 微信支付
- **Then** 支付成功并生成订单
- **And** 能看到取餐号或制作进度

### P03: 外卖下单

对应 User Stories: 5, 6, 8, 10

- **Given** 顾客已进入点单流程且可选外卖
- **When** 顾客选择外卖、填写地址、结算并微信支付
- **Then** 生成外卖订单且支付成功

### P04: 查看我的积分

对应 User Stories: 9

- **Given** 顾客已登录或具备查看积分的身份
- **When** 顾客进入「我的积分」入口并打开积分页
- **Then** 能看到自己的当前积分信息

## 测试决策

- 手工验收：按 P01–P04 在微信开发者工具与真机预览走通。
- 优先自动化：菜单/购物车/订单状态等纯逻辑单测；支付与微信登录用模拟或沙箱，不在单元测试里打真实支付。
- 视觉：对照 `design/feiwai-logo.png` 核对首页品牌色与 Logo 展示。
- 上架前：走微信类目与支付相关审核清单（资质另备，不在本 PRD 展开）。
