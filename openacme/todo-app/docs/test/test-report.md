## 5. 缺陷清单

### BUG-001 【低 · 健壮性】编辑 A 时删除其他条目，A 的未保存编辑内容静默丢失 —— **已修复（复测通过，关闭）**
- **严重度**：低（Low）
- **模块**：app.js 列表删除事件分支
- **复现步骤**：
  1. 新增 A、B 两条待办；
  2. 点击 A 的「编辑」，在编辑框输入新内容（不保存）；
  3. 点击 B 的「删除」。
- **实际结果（修复前）**：A 的编辑态被强制退出，编辑框消失，未保存的新内容丢失，无任何提示；A 显示存储中的原标题。
- **修复方案（任务 #8，保留编辑态）**：`rerender()` 重建前记录进行中编辑的 `{id, 未保存值}`，重建后若条目仍存在则以原值恢复编辑态（含焦点）；同一根因的勾选/新增路径一并修复。
- **复测结果（2026-08-11）**：E2E T14 / R1 / R2 / R3 / R4b 全部 PASS —— 删除/勾选/新增其他条目均保留编辑态与未保存内容；恢复后保存生效；被编辑条目已被外部删除时不恢复编辑态、不崩溃。**缺陷关闭。**

### BUG-002 【低 · UX】编辑空标题保存时错误提示位置错误，且取消后残留 —— **已修复（复测通过，关闭）**
- **严重度**：低（Low）
- **模块**：app.js `saveEdit` / `enterEdit`
- **复现步骤**：
  1. 编辑某条待办，清空标题，点「保存」；
  2. 观察提示位置；随后点「取消」。
- **实际结果（修复前）**：
  - 错误提示「待办内容不能为空」显示在**页面顶部添加区**（`#add-error`），而非编辑行内；
  - 取消编辑后，该提示残留不消失；
  - `enterEdit` 创建的行内错误元素（`errEl`）从未被填充，为死代码。
- **修复方案（任务 #8）**：行内错误元素提升为模块级 `editErrorEl`（与 `editInput` 同生命周期，`exitEdit` 清空）；空标题保存提示显示在编辑行内（`p.field-error.inline`）；编辑输入时清除行内提示与红边；`#add-error` 不再被编辑流程污染。
- **复测结果（2026-08-11）**：E2E R5 / R6 / R7 全部 PASS —— 提示显示在编辑行内、顶部添加区无内容且隐藏；继续输入清除提示与红边；取消后无残留、原值保留。**缺陷关闭。**

## 6. 风险与建议

| # | 风险/建议 | 说明 | 处置 |
|---|-----------|------|------|
| 1 | file:// 真机冒烟 | 本机无浏览器，file:// 场景经静态检查确认可行（经典脚本、无跨域依赖），jsdom 因 opaque origin 限制无法模拟 file:// 的 localStorage | 建议 PM/开发代表在真实浏览器（Chrome/Edge/Firefox）打开 `index.html` 补一轮冒烟：新增 → 刷新 → 数据仍在 |
| 2 | ESM→经典脚本偏离 | dev-plan 指定 ESM，开发改经典脚本 + UMD，理由充分 | 需 dev-lead/PM 知悉确认（developer 已声明） |
| 3 | 多标签页不同步 | 同一浏览器多标签页不实时同步 | PRD §7 已声明接受，非缺陷 |
| 4 | localStorage 容量上限 | 约 5MB，溢出时已提示「保存失败」 | PRD §7 已声明接受 |
| 5 | 无回收站 | 误删不可恢复 | PRD §3.2 明确非目标 |
