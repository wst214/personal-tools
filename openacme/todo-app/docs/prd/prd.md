## 1. 背景与目标

老板目标：做一个**个人待办清单**，最小可用版（MVP），支持**增删改** + **本地存储**。

PM 已裁定 MVP 范围（见任务评论「PM 范围裁决」），本 PRD 将该范围固化为可测的验收标准。

**核心价值**：让用户能快速记录、管理自己的待办事项，数据保存在本人浏览器本地，无需联网、无需账号即可使用。

---

## 2. 用户与场景

### 2.1 目标用户
- **个人用户**：单个使用者在同一台设备上管理自己的待办。
- 无登录、无多用户——数据按设备（浏览器）隔离。

### 2.2 核心用户场景
1. **随手记录**：用户想到一件事，立刻新增一条待办（仅标题即可保存）。
2. **更新事项**：用户要修改某条待办的内容或完成状态。
3. **清理清单**：用户删除不再需要的待办。
4. **状态跟进**：用户标记某条为「已完成」或「未完成」，并希望**刷新/关闭浏览器后数据仍在**。

---

## 3. 范围

### 3.1 MVP 需求清单（本期做）
| # | 功能 | 说明 |
|---|------|------|
| F1 | 新增待办 | 输入标题，创建一条待办 |
| F2 | 编辑待办 | 修改已有待办的标题文本 |
| F3 | 删除待办 | 从清单中移除一条待办 |
| F4 | 标记完成/未完成 | 切换待办的完成状态 |
| F5 | 本地持久化 | 数据存于浏览器 localStorage，刷新/重开后仍在 |
| F6 | 清单展示 | 渲染全部待办，展示完成状态 |

### 3.2 非目标（本期明确不做）
| 排除项 | 理由 |
|--------|------|
| 云同步 / 多端同步 | 超出本地 MVP 范围，需账号与后端 |
| 多用户 / 登录 / 权限 | 单机个人使用，无账号体系 |
| 提醒 / 通知 | 需后台调度与推送能力，复杂 |
| 移动端原生 App | 本期为 Web 页面即可 |
| 拖拽排序 / 优先级排序 | 增加交互复杂度，非 MVP 必需 |
| 分类 / 标签 / 截止日期扩展字段 | 保持数据模型最小 |
| 撤销操作 / 回收站 | 数据删除即为最终，MVP 不做软删除恢复 |

> 原则：**非目标即明确排除**，避免范围蔓延。若后期需要，另开迭代。

## 4. 数据模型

本地存储的待办条目：

```json
{
  "id": "uuid-v4 字符串",
  "title": "待办标题（非空，去首尾空白）",
  "done": false,
  "createdAt": "ISO 8601 时间戳",
  "updatedAt": "ISO 8601 时间戳"
}
```

- **存储键**：localStorage 单一键，例如 `todo.items`，值为上述条目的 JSON 数组。
- **约束**：
  - `id` 全局唯一（创建时生成）。
  - `title` 必填，去首尾空白后非空；否则禁止提交。
  - `done` 布尔值，默认 `false`。
  - `createdAt` 创建时间；`updatedAt` 每次修改更新。

## 5. 用户故事与验收标准（可测）

| 用户故事 | 验收标准（Given-When-Then） |
|----------|------------------------------|
| US1 新增待办 | Given 清单页；When 输入非空标题并提交；Then 新待办出现在清单中，`done=false`，写入 localStorage |
| US1a 空标题校验 | When 标题去首尾空白后为空仍提交；Then 拒绝创建，提示用户 |
| US2 编辑待办 | When 修改某待办标题并保存；Then 清单显示新标题，`updatedAt` 更新，localStorage 同步 |
| US3 删除待办 | When 删除某待办；Then 该条从清单与 localStorage 中移除，其余不变 |
| US4 标记完成/未完成 | When 切换某待办完成状态；Then `done` 值反转，状态视觉更新，localStorage 同步 |
| US5 本地持久化 | Given 已有若干待办；When 刷新页面或关闭重开浏览器；Then 所有待办及其状态完整恢复 |
| US6 清单展示 | Given 存在待办；When 打开页面；Then 按固定顺序渲染全部待办，完成项与未完成项可区分 |

## 6. 关键页面/交互说明（原型文字稿）

### 6.0 页面结构（单页）
```
┌──────────────────────────────────────┐
│ 顶部：标题「我的待办」                    │
│ 输入区：文本框 + 「添加」按钮               │
│ ┌──────────────────────────────────┐ │
│ │ 待办列表（逐行）                       │ │
│ │  [完成勾选框] 标题文本   [编辑][删除]    │ │
│ │  ...                              │ │
│ └──────────────────────────────────┘ │
└──────────────────────────────────────┘
```

### 6.1 新增
- 顶部文本框输入标题，点击「添加」或回车提交。
- 空标题（去空白后）不创建，就地提示。

### 6.2 标记完成
- 每行左侧勾选框，点击切换 `done` 状态；完成项标题加删除线/变灰以示区分。

### 6.3 编辑
- 点击「编辑」进入行内编辑（文本框预填当前标题），保存后更新；取消则放弃。

### 6.4 删除
- 点击「删除」立即移除该行，无需二次确认（MVP 简化）。

## 7. 风险与假设

| 风险 | 说明 | 缓解 |
|------|------|------|
| Privacy/存储限制 | localStorage 容量有限（约 5MB），超大清单可能溢出 | MVP 数据量小可接受；溢出时给出错误提示 |
| 数据不可迁移 | 纯本地，换设备/清缓存即丢失 | 属非目标（无云同步），已在范围中声明 |
| 单浏览器隔离 | 同一浏览器不同标签页需手动刷新同步 | MVP 接受；不做跨页实时同步 |
| 无回收站 | 误删不可恢复 | MVP 明确删除即最终 |

**假设**：目标运行环境为现代浏览器且支持 localStorage；单页应用，无需后端。

---

## 8. 优先级与裁决理由

按 PM 裁定，全部 MVP 功能（F1–F6）为 **P0 必做**，一次交付。

**裁决理由**：
- 增删改 + 标记完成是「待办清单」产品的最小闭环，缺一不可用。
- localStorage 持久化是「本地存储」目标的核心，为 P0。
- 其余（云同步、提醒、排序、多用户等）优先级低且依赖外部能力/账号体系，明确拆为非目标，防止首版范围膨胀。
