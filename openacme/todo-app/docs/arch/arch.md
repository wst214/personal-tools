## 1. 技术选型

### 1.1 结论：纯前端静态方案（HTML / CSS / 原生 JS + localStorage）

| 维度 | 选型 | 理由 |
|------|------|------|
| 架构形态 | 静态前端单页应用（SPA） | 本地存储 MVP，无后端、零部署——直接打开 `index.html` 即用 |
| 语言/框架 | 原生 JavaScript（ES Modules）+ HTML + CSS | 无框架依赖、零构建，契合最小交付成本；数据量小无需响应式框架 |
| 持久化 | `localStorage`（浏览器本地） | 契合「本地存储」目标，刷新/重开仍在，无需账号与网络 |
| 模块化 | 原生 ES Modules（`import`/`export`） | 无需打包器即可模块化，且为数据层单测铺路 |
| 测试 | Node 内置测试运行器 / 轻量 runner 直测数据层 | 数据层为纯 JS（无 DOM 依赖），可在 Node 直接跑单测 |

### 1.2 选型理由（对照目标）

- **无需后端**：全部数据在浏览器本地读写，无网络请求、无服务端状态，因此不需要任何后端服务。
- **零部署**：静态文件方式交付，浏览器直接打开即可；可后续挂到任意静态托管（如 GitHub Pages / 任意 CDN）。
- **最小成本**：不使用框架、不引入构建链，developer 实现与测试路径最短。
- **可测性**：通过把「数据层」抽成**与 DOM 解耦的纯模块**，可在 Node 环境直接进行单元测试，弥补无浏览器 E2E 时的测试覆盖。

> 说明：PM 允许「轻量调整以支撑单测」。本方案不加构建链，仅采用原生 ES Modules + 纯数据层，测试用 Node 直测数据层，故不引入额外框架/打包器，保持零部署目标。

### 1.3 明确不做（架构层面同样排除）
- 无后端 API、无数据库、无云同步。
- 无构建工具链（打包器、转译器、CSS 预处理器）。
- 无路由（单页单视图，不需前端路由）。

## 2. 模块划分与边界

三层职责分离，数据层与渲染层通过**状态托管**解耦，交互层仅做事件转发。

```
┌─────────────────────────────────────────────┐
│  index.html（单页入口，组织静态结构）            │
│   ┌───────────────┐   ┌──────────────────┐  │
│   │  render.js     │   │  store.js         │  │  ← 数据层（纯 JS，可测）
│   │  (渲染层)      │   │  localStorage 封装  │  │
│   │   DOM 渲染      │   │  增删改查/持久化     │  │
│   └───────┬───────┘   └────────┬─────────┘  │
│           │ 读取状态/触发操作       ▲          │
│   ┌───────┴───────┐             │          │
│   │  app.js (交互层)             │          │
│   │  事件绑定/表单校验/编排        └──────────┘
│   └───────────────┘
└─────────────────────────────────────────────┘
```

### 2.1 模块职责

#### `store.js` — 数据层（状态管理 + localStorage 封装）
- **职责**：作为唯一数据源，封装所有对条目数据的读取与写入；
  - CRUD：`list()`、`add(title)`、`update(id, patch)`、`toggleDone(id)`、`remove(id)`；
  - 持久化：每次变更后写回 localStorage；
  - 校验：`title` 去首尾空白后非空校验，生成 `id`/`createdAt`/`updatedAt`。
- **边界**：**不引用任何 DOM API**，不依赖浏览器事件——纯 JS 模块，可被 Node 直接测试。
- **对外接口**：只暴露纯函数/方法，不直接暴露 localStorage 原生对象。

#### `render.js` — 渲染层
- **职责**：把 `store.list()` 的状态渲染为 DOM；
  - 渲染待办列表（每行：勾选框 + 标题 + 编辑/删除按钮）；
  - 完成项视觉区分（删除线/变灰）；
  - 提供「空状态」提示。
- **边界**：**只读状态、只写 DOM**，不直接改动数据；数据变更一律通过 `store` 方法。

#### `app.js` — 交互层（编排）
- **职责**：事件绑定与流程编排；
  - 新增：读取输入框 → 调 `store.add` → 触发重渲染；
  - 编辑：进入行内编辑 → 保存/取消 → 调 `store.update` → 重渲染；
  - 删除：调 `store.remove` → 重渲染；
  - 标记：调 `store.toggleDone` → 重渲染；
  - 表单校验：空标题就地提示，不进入数据层。
- **边界**：连接 DOM 事件与数据层，不直接写 localStorage，不直接做复杂状态逻辑。

#### `index.html` — 静态入口
- 声明页面结构（标题、输入区、列表容器），按需引入上述模块。

### 2.2 依赖方向（单向）
- `app.js → store.js`（写数据）
- `app.js → render.js`（读状态 / 触发重渲染）
- `render.js → store.js`（读状态）
- **禁止反向依赖**：`store.js` 不得依赖/引用 DOM 或 render。

## 3. localStorage 键约定与序列化格式

### 3.1 键（单一键）
- **键名**：`todo.items`
- **值**：一条 JSON 字符串，内容为条目数组（见下）。

> 选择单一键：数据量小、结构简单，一次读写即可完成整份持久化，避免多键一致性问题。

### 3.2 序列化格式

存储值（`todo.items`）：
```json
[
  {
    "id": "uuid-v4 字符串",
    "title": "待办标题",
    "done": false,
    "createdAt": "ISO 8601 时间戳",
    "updatedAt": "ISO 8601 时间戳"
  }
]
```

- 顶层为 **JSON 数组**（可能为空数组 `[]`）。
- 条目字段与 PRD §4 数据模型一致。
- 序列化：`JSON.stringify`；反序列化：`JSON.parse`。

### 3.3 读写约定
- **读**：启动时 `JSON.parse(localStorage.getItem('todo.items'))`；为空/非法时回退为 `[]`。
- **写**：每次变更后 `localStorage.setItem('todo.items', JSON.stringify(items))`，**全量覆盖**（MVP 数据量小，全量写最简单可靠）。
- **异常处理**：
  - `JSON.parse` 失败（数据损坏）→ 回退空数组并给出控制台告警，不崩溃；
  - `setItem` 抛错（如 5MB 容量溢出 / 隐私模式禁用）→ 捕获并向上提示「保存失败」，不静默丢失。

## 4. 数据流（增/删/改/标记）

统一模式：**事件 → 调用数据层方法 → 数据层更新数组并持久化 → 重渲染**。

### 4.1 新增（US1 / US1a）
```
输入框标题 → [app.js] 校验非空？
  ├─ 否 → 就地提示，不进入数据层，流程终止
  └─ 是 → store.add(title)
              ├─ 生成 id / createdAt / updatedAt，done=false
              ├─ 追加到数组
              ├─ setItem 持久化
              └─ 返回新条目
         → [app.js] 调 render 重渲染全列表
```

### 4.2 编辑（US2）
```
点击编辑 → 行内编辑表单 → 保存
  → store.update(id, { title: 新标题 })
      ├─ 校验新标题非空
      ├─ 更新 title 与 updatedAt
      ├─ setItem 持久化
  → 重渲染；取消则放弃不写
```

### 4.3 删除（US3）
```
点击删除 → store.remove(id)
  ├─ 从数组移除该条目
  ├─ setItem 持久化
  → 重渲染，其余条目不变
```

### 4.4 标记完成/未完成（US4）
```
点击勾选框 → store.toggleDone(id)
  ├─ 反转该条 done 值
  ├─ 更新 updatedAt
  ├─ setItem 持久化
  → 重渲染（完成项删除线/变灰）
```

### 4.5 启动加载（US5 / US6）
```
页面加载 → [app.js] 读取 store.list()（内部从 localStorage 解析）
  → render 渲染全部条目（含完成状态）
  → 刷新/重开浏览器时数据从 localStorage 恢复
```

> 一致性保证：**所有写操作都收敛到 `store.js` 的单一入口**，每次变更必然伴随持久化，避免「内存有/存储无」的不一致。

## 5. 测试可测性设计

### 5.1 分层可测性
- **数据层 `store.js` 为纯 JS**：不依赖 DOM、不依赖浏览器对象，可在 Node 环境直接运行单元测试。
- **设计要点**：
  - `store.js` 对 localStorage 的访问通过**可注入的存储适配器**（默认传 `window.localStorage`，测试时注入内存 mock），使测试无需真实浏览器。
  - 数据层方法为**确定性纯逻辑**（输入 → 校验 → 变更 → 返回），便于断言。
- **渲染层/交互层**：MVP 逻辑简单，建议以「数据层单测 + 浏览器手动/冒烟验证」为主；如有精力可加 DOM 层面的轻量测试，但非强制。

### 5.2 建议测试用例（开发者据此实现）
| 层 | 用例 |
|----|------|
| store | `add` 合法标题 → 追加且 `done=false`、生成 id/时间戳 |
| store | `add` 空白标题 → 拒绝/抛错，不写入 |
| store | `update` 修改标题 → `title` 与 `updatedAt` 更新 |
| store | `toggleDone` → `done` 值反转 |
| store | `remove` → 条目移除，其余不变 |
| store | 序列化往返 → `setItem` 内容可被 `getItem`+`parse` 还原，刷新后数据完整（US5） |
| store | 损坏数据（非法 JSON）→ 回退空数组不崩溃 |
| store | 启动加载 → 空存储返回 `[]` |

## 6. 风险与运维/安全提示

| 类别 | 风险 | 说明与缓解 |
|------|------|-----------|
| 容量 | localStorage ~5MB 上限 | MVP 数据量小可接受；`setItem` 溢出时捕获并提示「保存失败」，不静默丢数据 |
| 数据损坏 | 存储值非预期（被篡改/半写） | 读取时 `JSON.parse` 失败回退空数组并告警，不崩溃 |
| 隐私模式 | 部分浏览器私隐模式禁用 localStorage | `getItem`/`setItem` 抛错时捕获并提示，应用降级为「不可持久化」仍可运行 |
| 数据丢失 | 纯本地，清缓存/换设备即丢 | 属 PRD 非目标（无云同步），已在范围中声明 |
| 跨页同步 | 多标签页需手动刷新 | PRD 明确 MVP 接受，不做实时同步 |
| 安全 | `title` 为用户输入，渲染进 DOM | 开发须用 `textContent`/`createTextNode` 防 XSS，**禁止 innerHTML 拼接用户输入** |
| 运维 | 零后端、零部署 | 无运维面；发布即复制静态文件到任意静态托管 |

## 7. 关键架构决策（ADR 摘要）

完整决策记录见 `docs/arch/adr.md`。核心结论：
1. **纯前端静态 + localStorage** ✅（采纳，契合本地 MVP、零部署）。
2. 数据层抽为**纯 JS 模块 + 可注入存储** ✅（支撑单测，无引入框架之代价）。
3. 单一存储键 `todo.items` 全量覆盖写 ✅（数据量小，简单可靠优于多键分片）。
4. 显式排除：后端、构建链、路由、跨页同步。
