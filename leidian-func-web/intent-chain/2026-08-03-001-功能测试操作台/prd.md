## 问题陈述

预警规则配置与压住预警相关功能开发完成后，测试同学需要按功能模块整理用例、勾选执行，并对每条用例看到通过/失败结果。目前缺少像 PERF 压测台那样、面向功能点的本地操作台，用例难维护、难选择性复跑、结果不直观。

## 方案

做独立本地工具 `leidian-func-web`：仿 PERF 压测台的面板/标签页风格；按模块维护用例并以文件落盘；配置被测环境后勾选批量自动请求 HTTP 接口并用判定条件核对；逐条展示结果并保留历史。首期内置「预警规则配置」「压住预警」两套用例包。无不可妥协项。

## 用户故事

1. As a 测试人员, I want 按功能模块分组查看和维护用例, so that 能按业务模块组织功能测试 [C01]
2. As a 测试人员, I want 新增、编辑、删除用例（含步骤、请求与判定条件）, so that 功能点变更后能同步更新用例 [C02]
3. As a 测试人员, I want 勾选若干用例后一键批量执行, so that 只跑当前关心的功能点 [C03]
4. As a 测试人员, I want 每条用例都显示通过或失败及失败原因, so that 能快速定位问题 [C04]
5. As a 测试人员, I want 查看历史执行记录, so that 能对照以往跑批结果 [C05]
6. As a 测试人员, I want 配置被测网关/服务地址和登录凭证, so that 能对目标环境发起请求 [C06]
7. As a 测试人员, I want 直接使用内置的预警规则配置用例包, so that 规则 CRUD/启停等功能点开箱可测 [C07]
8. As a 测试人员, I want 直接使用内置的压住预警用例包, so that 申请到终止等流程可测（接口未齐时可跳过并说明原因） [C08]
9. As a 测试人员, I want 操作台界面与 PERF 压测台观感一致, so that 学习成本低、操作习惯统一 [C09]
10. As a 测试人员, I want 用例以 JSON/YAML 文件保存并可进 Git, so that 用例能与功能版本一起演进 [C10]
11. As a 测试人员, I want 系统自动发 HTTP 请求并用判定条件判定通过/失败, so that 不必手工逐条点接口 [C11]

## 实现决策

- **形态**：独立仓库 `D:\mytools\leidian-func-web`，不并入业务仓；结构对齐 `leidian-perf-web`（`web/` 静态前端 + 本地 Python HTTP 服务）。
- **页面分区（建议标签）**：环境与准备 → 用例维护 → 执行与结果 → 历史记录。
- **用例存储**：按模块目录存放 YAML/JSON（如 `cases/warn-rule/`、`cases/warn-suppress/`）；支持增删改后写回文件。
- **用例模型（最小）**：id、模块、名称、步骤列表（method/path/headers/body）、判定条件（状态码、JSONPath/字段期望）、可选依赖与跳过标记。
- **执行引擎**：服务端按勾选顺序发 HTTP 请求到配置的 Base URL，带登录凭证；逐步断言；汇总每条结果（通过/失败/跳过 + 原因 + 关键响应摘要）。
- **历史**：每次跑批写入 `data/runs/`（或等价），可列表打开明细。
- **首期用例包**：
  - 预警规则：对齐现有 `/warning/rules`（列表、详情、新建草稿、编辑、启用、停用、删除）。
  - 压住预警：按设计流程预置用例；接口未就绪时标记跳过并给出原因，不记为失败。
- **不做**：嵌入业务前端、手工改写自动结果、覆盖其他业务模块（设备/雷达等留后续扩展）。

## 验收标准

### P01: 维护用例

对应 User Stories: Story 1, 2, 10

- **Given** 操作台已启动，存在「预警规则配置」或「压住预警」模块
- **When** 在对应模块下新增或编辑一条用例并保存
- **Then** 用例出现在该模块列表中
- **And** 重启操作台后该用例仍可从用例文件中加载

### P02: 配环境并跑批

对应 User Stories: Story 3, 4, 6, 11

- **Given** 已填写被测 Base URL 与登录凭证，且至少勾选一条可执行用例
- **When** 点击批量执行
- **Then** 系统对每条勾选用例自动发起 HTTP 请求
- **And** 每条用例展示通过或失败
- **And** 失败用例可见失败原因（如状态码不符或判定条件未满足）

### P03: 规则用例包

对应 User Stories: Story 7

- **Given** 被测环境已启动且预警规则接口可用，环境配置正确
- **When** 执行内置预警规则用例包中的用例
- **Then** 各用例结果与接口实际行为一致（通过/失败判定正确）

### P04: 压住预警用例包

对应 User Stories: Story 8

- **Given** 已加载压住预警用例包
- **When** 执行该包中的用例
- **Then** 接口可用时给出通过或失败结果
- **And** 接口未齐时结果为跳过并带有明确原因（不记为失败）

### P05: 查历史

对应 User Stories: Story 5

- **Given** 至少完成过一次跑批
- **When** 打开历史记录并选择该次跑批
- **Then** 可见该次各用例的结果明细

### P06: 视觉风格

对应 User Stories: Story 9

- **Given** 操作台首页可访问
- **When** 浏览各主要标签页
- **Then** 可见与 PERF 压测台一致的面板、标签页、徽章与绿系配色操作台观感

## 测试决策

- **工具自测**：用例文件读写、跑批编排、判定条件引擎用单元/集成测试（不依赖真实业务库）。
- **联调验收**：对已启动的 `biz-service`（经网关或直连）跑内置预警规则用例包；压住预警在接口就绪后再做联调。
- **参考**：`leidian-perf-web` 的本地服务 + 任务状态/结果回写模式；业务接口以 `WarnRuleController` 与设计文档为准。
- **UI**：对照 `leidian-perf-web/web` 做观感核对（P06），不做像素级回归。
